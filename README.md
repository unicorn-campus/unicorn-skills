# unicorn-skills

Claude Code용 스킬 모음. 기획 산출물을 아키텍처 설계서로, 설계서를 실행 가능한 코드로 옮기는 파이프라인과
프롬프트 개선ㆍ개념 설명 도구를 제공.

## 스킬 목록

| 스킬 | 설명 |
|------|------|
| [design-architecture](#design-architecture) | 기획 산출물 → AI 앱 아키텍처 설계서 7종 생성 |
| [develop-agentic-ai](#develop-agentic-ai) | 아키텍처 설계서 7종 → 실행 가능한 코드·시험·README 생성 |
| [prompt-enhancer](#prompt-enhancer) | 프롬프트를 가이드 기준으로 개선 |
| [eli5](#eli5) | 주제를 배경지식 0인 사람에게 그림 위주 HTML 1장으로 설명 |

## design-architecture

기획 산출물(비즈니스모델·유저스토리·이벤트스토밍)을 입력으로 AI 앱 아키텍처 설계서 7종
(목표/품질 카드 → 논리아키텍처 → 워크플로우 → 역할계약서 ⇄ 지식/도구 → 관측/가드레일 → 배포)과
반영대조표 1종을 정해진 순서로 생성한다.

**트리거 키워드**: "아키텍처 설계", "설계서 작성", "논리아키텍처", "워크플로우 설계", "역할계약서"

**사용법**
1. Claude Code에서 스킬을 호출하면 기획 산출물 디렉토리와 설계서 출력 디렉토리를 묻는다.
2. 기획 산출물(비즈니스모델·유저스토리·이벤트스토밍 문서)이 있는 절대경로를 입력한다.
3. 설계서 7종과 반영대조표가 지정한 출력 디렉토리에 순서대로 생성된다.

**입력 예시 위치**: `prompts/_shared/프로젝트정보.md`에 프로젝트 정보(V-01~V-12)를 먼저 채워야 함.

## develop-agentic-ai

아키텍처 설계서 7종을 입력으로 개발 프롬프트 9종(런타임·데이터셋·지식경로·커넥터·가드레일·워크플로우·
API/UI·배포·평가)을 정해진 순서로 호출해 실행 가능한 코드·시험·README를 생성한다.

**트리거 키워드**: "개발 시작", "코드 생성", "개발 프롬프트 실행", "설계서를 코드로"

**사용법**
1. `design-architecture` 스킬로 설계서 7종을 먼저 만들어 둔다(선행 조건).
2. 스킬을 호출하면 기획 산출물 경로, 설계서 경로, 프론트엔드 스택, 코드 루트 경로, 상태 저장 백엔드를 묻는다.
3. 답변 후 개발 프롬프트 9종이 순서대로(일부 병렬) 실행되어 코드 루트 경로 하위에 코드·시험·README가 생성된다.

**입력 예시 위치**: `prompts/_shared/개발환경정보.md`에 개발 환경 정보(D-01~D-12)가 채워짐(스킬이 대상 프로젝트에 인스턴스를 생성).

## prompt-enhancer

사용자가 제공한 프롬프트를 프롬프트 작성 가이드(구체성·업무배분·하네스 측면)에 따라 개선한다.

**트리거 키워드**: "프롬프트 개선", "프롬프트 수정"

**사용법**
1. 스킬을 호출하면 프롬프트 원문을 파일 경로로 줄지, 대화창에 직접 붙여넣을지 묻는다.
2. 구체성, 업무배분, 하네스 3가지 관점에서 병렬로 개선안을 만들고 Critic이 비판적으로 검토한다.
3. 최종 개선 결과가 `{프로젝트 디렉토리}/prompts/{file-name}_v{N}.txt`로 저장된다.

**참고 자료**: `references/prompt-guide.md`

## eli5

주제 하나를 그 분야 배경지식이 전혀 없는 사람에게 전달하기 위해, 큰 그림이 설명을 지고 글은 라벨
역할만 하는 HTML 아티팩트 1장을 생성한다. 기존 문서를 짧게 줄이는 것이 아니라 설명의 매체를
글에서 그림으로 바꾸는 스킬이다.

**트리거 키워드**: "/eli5", "쉽게 설명", "그림으로 설명", "초등학생도 알게", "이해가 안 돼"

**사용법**
1. `/eli5 {주제}` 형태로 주제를 함께 주면 되묻지 않고 바로 진행한다(주제가 없을 때만 문의).
2. 리포 내부 주제면 실제 소스ㆍ설계서를 읽고, 일반 개념이면 아는 지식으로, 최신ㆍ불확실한 사실이면
   웹 검색으로 확인한 뒤 설명한다.
3. 주제 유형에 맞는 그림 형태를 고르고, 자가 점검 5항목을 통과한 HTML 아티팩트를 발행한다.

**참고 자료**: `references/설명패턴.md`(유형별 그림 형태 선택표ㆍ비유 기준ㆍ자주 나오는 실패)

**출처**: 원본 아이디어는 Anthropic 커뮤니티 마켓플레이스의
[eli5 플러그인](https://github.com/anthropics/claude-plugins-community/tree/main/eli5)(MIT).
이 리포 버전은 해당 한 줄 프롬프트를 이 리포의 스킬 작성 규격에 맞춰 확장한 것이다.
