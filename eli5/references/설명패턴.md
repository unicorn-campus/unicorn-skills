# 설명 패턴 표

주제 유형별로 어떤 그림 형태를 쓸지 고르는 표. `SKILL.md` [처리] 3단계에서 참조함.
표에 없는 유형이면 가장 가까운 행을 고르되, 문단 나열로 돌아가지는 않음.

## 1. 유형별 패턴 선택

| 주제 유형 | 질문 형태 | 그림 형태 | 핵심 규칙 |
|---|---|---|---|
| 흐름ㆍ절차 | "어떻게 동작해?" | 좌→우 단계 화살표 | 단계는 3~5개. 각 단계에 "무엇이 들어와 무엇이 나가는지"를 라벨로 |
| 구조ㆍ구성 | "뭐로 이뤄져 있어?" | 상자 안의 상자(중첩 박스) | 포함 관계만 그림. 상호작용은 흐름형으로 따로 |
| 비교ㆍ선택 | "A랑 B 뭐가 달라?" | 좌우 2단 대조 | 같은 항목을 같은 높이에 둠. 차이 나는 칸만 색으로 강조 |
| 관계ㆍ연결 | "얘네가 어떻게 얽혀 있어?" | 노드-엣지 그래프 | 노드 7개 이하. 넘으면 그룹으로 묶음 |
| 시간ㆍ변화 | "어쩌다 이렇게 됐어?" | 가로 타임라인 | 사건이 아니라 **무엇이 바뀌었는지**를 라벨로 |
| 크기ㆍ비율 | "얼마나 큰데?" | 면적ㆍ길이 비교 도형 | 아는 것(사람ㆍ버스ㆍ서울)을 옆에 두고 비교 |
| 조건ㆍ분기 | "언제 뭘 써?" | 의사결정 트리 | 분기는 2갈래씩. 잎에 결론을 한 단어로 |
| 오해 교정 | "이거 ○○인 줄 알았는데?" | 틀린 그림 ↔ 맞는 그림 | 틀린 쪽을 먼저 보여주고 어디가 다른지 한 곳만 짚음 |

## 2. 비유 고르는 기준

- **일상에서 이미 겪은 것**을 씀: 우체국, 식당 주방, 아파트 경비실, 도서관, 은행 창구, 지하철 환승
- 비유는 **주제당 1개로 통일**함. 상자를 우체국으로 비유했으면 끝까지 우체국으로 감.
  중간에 비유가 바뀌면 독자는 두 개를 다 이해해야 함
- 비유가 깨지는 지점이 있으면 **그 지점을 명시**함("여기까지만 우체국이고, 이 다음은 다름")
- 비유가 안 떠오르면 주제를 아직 이해 못 한 것임. 설명을 짜기 전에 주제부터 다시 확인

## 3. 글 줄이는 기준

| 쓰고 싶은 것 | 대신 하는 것 |
|---|---|
| "A는 B를 호출하고 C에 저장한다" | A→B→C 화살표 3개, 글 0줄 |
| 정의 문단 | 도형 안의 한 단어 라벨 |
| 장점 3가지 불릿 | 비교 2단에서 색으로 표시된 칸 |
| 예외 상황 설명 | 점선 화살표 1개 + 라벨 한 단어 |
| 배경ㆍ역사 문단 | 뺌(첫 설명에는 필요 없음) |

## 4. 자주 나오는 실패

- **그림을 그렸는데 옆에 설명 문단도 다 씀** → 문단이 있으면 그림을 안 봄. 문단을 지움
- **아이콘만 예쁘게 깔림** → 아이콘은 그림이 아님. 관계를 나타내는 선ㆍ배치가 있어야 그림임
- **전문 용어를 그대로 라벨에 씀**("Ingress Controller") → 일상어 라벨을 크게, 원어를 작게 병기
- **한 장에 다 넣으려다 글씨가 작아짐** → 주제를 좁힘. 못 좁히면 덩어리 수를 줄임
- **정확하게 쓰려다 원문 문서가 됨** → 이 산출물의 독자는 처음 듣는 사람. 정밀도보다 첫 그림이 먼저
