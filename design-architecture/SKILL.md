[목표]
기획 산출물(비즈니스모델·유저스토리·이벤트스토밍)의 값을 아키텍처 설계로 옮기기 위하여,
사용자가 지정한 기획 산출물 디렉토리를 입력으로 아키텍처 설계서 7종
(목표/품질 카드 → 논리아키텍처 → 패턴/시퀀스 → 역할계약서 ⇄ 지식/도구 → 가드레일/관측 → 배포)과
반영대조표 1종을 정해진 순서로 생성하는 유저스코프 스킬 실행

[역할]
`AGENTS.md` design-agentic-ai 팀의 오케스트레이터 클로니가 산출물별 담당자에게 실제 위임하여
진행함. 담당자 전환은 문서상 서술로 끝내지 않고 `Agent` 도구로 해당 서브에이전트를 실제 호출함
(AGENTS.md "패턴은 문서상 선언이 아니라 실제 Agent 호출로 실행함" · 정직한 보고 규칙). 담당자
배정표·판정 근거·협업 패턴 분류는 [처리] 0단계에 둠(역할 섹션은 원칙만 선언).

[맥락]
- 내 상황: `prompts/design/` 프롬프트 7종과 `guides/` 가이드 7종을 매번 손으로 복사해 AI 코딩 도구에
  붙여 넣던 방식을 스킬로 패키징해 재사용하고 싶음. 종전 방식은 인격만 바꿔 한 명이 전부 썼으나,
  이번 개선으로 실제 팀원 서브에이전트(flonie/jisikni/connectni)에게 위임하도록 바꿈
- 결과물 독자: 이 스킬을 실행하는 프로젝트의 아키텍트·개발자. 산출물은 뒤 단계(개발·배포) 담당자가
  그대로 읽고 구현 근거로 삼음
- 비용 특성: 가이드 7종은 각 단계 자가 점검에만 쓰이는 절이 있어, 전문을 매 단계 반복해 읽으면
  같은 내용을 여러 번 컨텍스트에 태우는 낭비가 생김 — [처리]에서 발췌 읽기로 제한함
- 서브에이전트는 매 호출마다 컨텍스트가 새로 시작되므로, 호출 시 해당 단계 프롬프트 파일 전문 +
  프로젝트정보.md 중 그 단계가 쓰는 변수 + 직전 단계 산출물 중 참조가 필요한 절만 전달하고,
  대화 이력 전체나 가이드 전문은 전달하지 않음(비용 최소화)

[입력]
- 기획 산출물 Base 디렉토리: 스킬 실행 시작 직후 AskUserQuestion으로 입력받는 절대경로
  (비즈니스모델·유저스토리·이벤트스토밍 산출물 파일이 있는 디렉토리)
- 아키텍처 설계서 Base 디렉토리: 스킬 실행 시작 직후 같은 AskUserQuestion 호출로 함께 입력받는
  절대경로(미존재 시 신규 생성 대상, 이 디렉토리 하위에 설계 산출물 8건 저장)
- 프로젝트 정보 입력 양식: `{스킬 디렉토리}/prompts/_shared/프로젝트정보.md`(V-01 ~ V-12 변수 12종
  정의. 양식에 "원문의 개인정보·계정·시크릿·인증정보는 마스킹 후 기록" 안내문 포함)
- 설계 가이드 7종: `{스킬 디렉토리}/guides/01-*.md` ~ `07-*.md`(전문이 아니라 단계별로 필요한 절만
  발췌 참조)
- 설계 작성 프롬프트 7종: `{스킬 디렉토리}/prompts/01-*.md` ~ `07-*.md`(각 파일이 이미 8섹션 구조와
  담당자 프로파일·성향·경력, [출력] 섹션의 산출물 파일명 확정값을 포함하므로, Agent 호출 시 파일
  전문을 `prompt` 인자로 그대로 넘기면 별도 가공 없이 요건을 충족함)
- 담당 인격 매핑표·산출물 순서: `{스킬 디렉토리}/prompts/README.md` 2절(파일 목록의 "담당 인격"
  열이 산출물별 담당자를 이미 확정해 둠 — 아래 0단계는 이 표를 그대로 인용함)
- 공통 규약: `{스킬 디렉토리}/guides/README.md`, `{스킬 디렉토리}/prompts/README.md`(스킬 실행당
  최초 1회만 읽고 이후 단계에서 재독하지 않음)
- `{스킬 디렉토리}`: 이 SKILL.md 파일이 위치한 디렉토리의 절대경로(스킬 실행 환경이 자동 주입)

[처리]

### 0단계 — 담당 배정 확인 (실행 파일을 만들지 않는 판정 단계)
- `{스킬 디렉토리}/prompts/README.md` 2절 표에서 산출물별 담당 인격을 그대로 가져옴(재해석하지
  않음). 결과는 아래와 같음

| 산출물 | 담당 | subagent_type | 호출 방식 |
|---|---|---|---|
| ① 목표/품질 카드 | 클로니(직접) | — | Agent 호출 없음 |
| ② 논리아키텍처 | 클로니(직접) | — | Agent 호출 없음 |
| ③ 패턴/시퀀스 | 플로니 | `flonie` | Agent 호출 1회 |
| ④ 역할계약서 | 플로니 | `flonie` | Agent 호출 2회(초안 1회 + ⑤ 완료 후 갱신 1회) |
| ⑤ 지식/도구 | 지식니 | `jisikni` | Agent 호출 1회 |
| ⑥ 가드레일/관측 | 커넥니 | `connectni` | Agent 호출 1회 |
| ⑦ 배포 | 커넥니 | `connectni` | Agent 호출 1회 |
| `00-반영대조표.md` | 클로니(직접) | — | Agent 호출 없음(대응 프롬프트 없음, 최종 통합 성격) |

- ①②·00번은 `AGENTS.md` "적합한 팀원이 없는 경우 오케스트레이터가 직접 수행" + "클로니(직접
  수행): 최종 통합" 규칙에 따라 클로니 본인이 작성함
- 협업 패턴 판정: 전체 뼈대는 **파이프라인형**(각 프롬프트 `[입력]`의 "선행 산출물(필수)" 행이
  순서 고정·출력=입력 의존을 실증함). ④⇄⑤ 구간은 병렬 초안 없이 ④→⑤ 순차 완성 후 ④를 1회만
  되짚으므로 **파이프라인형의 되돌림(feedback) 1회 변형**으로 판정함(협업형·토론형 아님 — 트레이드
  오프 결정이 아니라 값 참조 동기화임)
- 모달니는 이 스킬 범위에 STT·TTS·VLM·요약 산출물이 없어 호출 대상 아님(정상)

### 1단계 — 입력 수집
- 스킬 실행 시작과 동시에 AskUserQuestion **1회** 호출로 기획 산출물 Base 디렉토리, 아키텍처 설계서
  Base 디렉토리 2건을 함께 입력받음(왕복을 줄이기 위해 분리 호출하지 않음)
- 기획 산출물 Base 디렉토리는 존재 여부와 하위 파일 개수(1개 이상)를 Glob으로 확인함
- 존재하지 않거나 하위 파일이 0개이면 AskUserQuestion으로 동일 항목을 재질문함(**재질문 카운터
  최대 2회**). 2회째도 미해결이면 실행을 중단하고 사유를 사용자에게 보고함(경로를 임의로 추정해
  진행하지 않음)
- 아키텍처 설계서 Base 디렉토리는 존재하지 않으면 신규 생성 대상으로 간주하고 재질문 없이 진행함

### 2단계 — 프로젝트 정보 채움 (한 번만)
- `{스킬 디렉토리}/prompts/_shared/프로젝트정보.md`의 변수 12종(V-01 ~ V-12) 구조를 그대로 가져와
  `{설계서 Base 디렉토리}/_shared/프로젝트정보.md`를 새로 만듦
- 값은 기획 산출물 Base 디렉토리의 원문에서만 채움. 원문에 근거가 없는 변수는 값 칸에
  `프로젝트 확정 필요`라고 적음(공란 금지 — 12종 전부 값 또는 `프로젝트 확정 필요`로 채움)
- 값을 채운 변수는 `[출처: {원문 파일명} - {절 또는 문단 제목}]` 형식의 근거 출처를 값 옆에 병기함
- 원문에 개인정보(실명·연락처·주민등록번호 등), 계정·시크릿·API 키·인증정보가 포함돼 있으면 원문
  그대로 옮기지 않고 마스킹 처리(예: 실명→가상 이름, 이메일·전화번호→형식만 남긴 예시, 키·비밀번호
  →`[마스킹됨]`)한 뒤 기록하고, 원문 위치(파일명·절)만 출처로 남김
- `V-11`(기획 산출물 경로)엔 1단계에서 입력받은 기획 산출물 Base 디렉토리 경로를, `V-12`(출력 루트
  경로)엔 1단계에서 입력받은 아키텍처 설계서 Base 디렉토리 경로를 그대로 적음
- `V-04`(데이터 원천)와 `V-10`(규제·안전 점검 항목)은 가이드 README의 「시작 전에 반드시 채울 것」
  절만 발췌해(전문 재독 금지) 항목을 하나씩 원문과 대조하여 O/X 임시 체크리스트를 만든 뒤, X 항목은
  `프로젝트 확정 필요`로 확정함
- 이 단계 종료 시점에 `프로젝트 확정 필요`가 남아 있고 그 변수를 이후 단계(③ ~ ⑦)가 실제 사용할
  예정이면, 다음 단계로 넘어가지 않고 즉시 AskUserQuestion으로 사용자에게 값 확정을 요청함

### 3단계 — 설계서 7종 순차 생성 (실행 순서: ① → ② → ③ → ④ ⇄ ⑤ → ⑥ → ⑦)

**①②(클로니 직접 작성)**
- `{스킬 디렉토리}/prompts/0N-*.md`(N=1,2)를 읽어 지시대로 직접 작성하고
  `{설계서 Base 디렉토리}/0N-*.md`에 저장함
- 작성 직후 그 프롬프트의 [처리] 자가 점검 단계를 스스로 실행함. 미통과 항목이 있으면 스스로
  고쳐 다시 점검하되 **재작성 카운터 최대 2회**까지만 반복함. 2회째도 미통과면
  `[확인필요: 미통과 사유]`를 표기하고 다음 산출물로 진행함(③~⑦과 동일 규칙)

**③~⑦(서브에이전트 실제 위임)**
- 인격만 바꿔 클로니가 대신 쓰지 않고 반드시 아래처럼 `Agent` 도구로 **실제 호출**함
  1. `{스킬 디렉토리}/prompts/0N-*.md` 프롬프트 파일 전체를 읽어, 그 안의 `프로젝트정보.md` 참조
     경로 문자열을 2단계에서 만든 파일의 실제 경로로 치환함
  2. 자가 점검에 필요한 가이드의 해당 절(통상 4절 점검표)만 Grep으로 찾음(가이드 `01~07-*.md`
     전문은 다시 읽지 않음)
  3. 서로 다른 출처의 텍스트를 하나의 `prompt` 인자에 담을 때는 반드시 XML 태그로 구분함 —
     `<프롬프트지시>{치환된 프롬프트 전문}</프롬프트지시>`,
     `<가이드점검표>{발췌한 4절 점검표}</가이드점검표>`,
     `<선행산출물>{직전 단계 산출물 중 참조가 필요한 절}</선행산출물>`
  4. `Agent(subagent_type="flonie"|"jisikni"|"connectni", description="설계서 0N-* 작성",
     prompt=<위 3종 태그를 이어붙인 문자열>, run_in_background=false)`로 호출함
  5. 앞 산출물이 다음 산출물의 필수 입력이므로(각 프롬프트 `[입력]`의 "선행 산출물(필수)" 행 참조)
     **순차(foreground) 호출만 하며 병렬 호출하지 않음**
  6. 호출 완료 후 Glob으로 산출물 파일이 실제 생성됐는지 확인한 뒤에만 다음 번호로 넘어감. 파일명은
     임의로 정하지 않고 해당 프롬프트의 [출력] 섹션에 명시된 값을 그대로 사용함(예: 01번은
     `01-목표품질속성카드.md`, 07번은 `07-배포설계.md`)
  7. 프롬프트 [처리]의 자가 점검 단계에서 미통과 항목이 있으면 같은 subagent_type을 재호출해
     고치되 **재작성 카운터 최대 2회**까지만 반복함. 재호출 시 `prompt`에는
     `<프롬프트지시>{원 프롬프트 전문}</프롬프트지시>`,
     `<직전산출물>{직전 호출이 만든 산출물 전체}</직전산출물>`,
     `<미통과항목>{점검표 미통과 항목 목록}</미통과항목>` 3종을 함께 전달함. 2회째도 미통과 항목이
     남으면 `[확인필요: 미통과 사유]`를 표기하고 다음 단계로 진행함(무한 재작성 금지)

### 4단계 — 되돌아가는 자리 2곳 반영 (파이프라인형의 되돌림 구간)
- ③ 완료 직후: 클로니가 직접 ①번 산출물 파일에서 "분해 결과 회신" 표를 찾아 ③번 산출물의 대응
  내용을 옮겨 적음(1회만 갱신, ①은 클로니 소유값이라 Agent 재호출 불필요). 해당 이름의 표가 없으면
  `[확인필요: 회신 칸 없음]`으로 남기고 다음 단계로 진행함
- ⑤ 완료 직후: `Agent(subagent_type="flonie", ...)`를 **다시 호출**하여(④ 초안 호출과는 별개의
