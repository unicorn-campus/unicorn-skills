[목표]
아키텍처 설계서 7종의 값을 실행 가능한 코드로 옮기기 위하여, 사용자가 지정한 기획 산출물ㆍ설계서
경로와 개발 환경 정보를 입력으로 개발 프롬프트 9종을 정해진 순서(파이프라인형 + 일부 병렬)로 호출해
코드ㆍ시험ㆍREADME를 생성하는 유저스코프 스킬 실행

[역할]
`AGENTS.md` design-agentic-ai 팀의 오케스트레이터 클로니가 프롬프트별 담당자에게 실제 위임하여
진행함. 담당자 전환은 문서상 서술로 끝내지 않고 `Agent` 도구로 해당 서브에이전트를 실제 호출함
(AGENTS.md "패턴은 문서상 선언이 아니라 실제 Agent 호출로 실행함" · 정직한 보고 규칙). 담당자
배정표ㆍ판정 근거ㆍ협업 패턴 분류는 [처리] 0단계에 둠(역할 섹션은 원칙만 선언).

[맥락]
- 내 상황: `{스킬 디렉토리}/prompts/` 개발 프롬프트 9종을 매 프로젝트마다 손으로 `개발환경정보.md`를 채우고
  순서를 기억해 하나씩 AI 코딩 도구에 복붙하던 방식을 스킬로 패키징해 재사용하고 싶음
- 결과물 독자: 설계서 7종을 이미 만들어 둔 개발자ㆍ아키텍트 — 이 스킬로 코드 생성을 시작함
- 이 스킬이 하지 않는 일: 설계서 7종을 만드는 일(`design-architecture` 스킬 소관) ㆍ 개발 프롬프트
  9종의 판단 기준을 새로 정하는 일(설계서와 `개발환경정보.md`가 이미 판단을 끝냄). 위임은 "전략을
  새로 정하는 일"이 아니라 "이미 정해진 값을 코드로 구현하는 일"에 한정됨
- 용어: `대상 프로젝트 루트`는 이 스킬을 호출한 시점의 현재 작업 디렉토리(cwd)를 가리킴. 이 값은
  사용자에게 묻지 않고 그대로 씀
- 비용 특성: 개발 프롬프트 9종은 파일당 100줄을 넘는 경우가 많음. 매 위임마다 파일 전문을
  오케스트레이터의 Agent 호출 인자 안에 다시 옮겨 적으면 같은 내용이 오케스트레이터ㆍ서브에이전트
  두 컨텍스트에 이중으로 쌓여 단계가 진행될수록 비용이 누적됨 — [처리]에서 경로만 전달하고
  서브에이전트가 직접 Read하게 하여 이중 적재를 막음

### 0단계 — 담당 배정 확인 (실행 파일을 만들지 않는 판정 단계)

### 1단계 — 입력 수집

- 스킬 실행 시작과 동시에 AskUserQuestion **1회** 호출로 [입력] 1ㆍ2ㆍ4행 5개 항목(기획산출물
  경로, 설계서 경로, 프론트엔드 스택, 코드 루트 경로, 상태저장 백엔드)을 함께 입력받음(왕복을
  줄이기 위해 분리 호출하지 않음)
- 기획 산출물 Base 디렉토리는 존재 여부와 하위 파일 개수(1개 이상)를 Glob으로 확인함
- 값이 없거나 경로가 비어 있으면 AskUserQuestion으로 동일 항목을 재질문함(**재질문 카운터 최대
  2회**). 2회째도 값이 없으면: 기본값이 있는 항목([입력] 2행)은 기본값으로 진행하고, 기본값이 없는
  항목([입력] 1ㆍ4행)은 사용자 응답이 올 때까지 다음 단계로 진행하지 않음(경로ㆍ선택값을 임의로
  추정해 진행하지 않음). 사용자가 "기본값으로 진행"이라 하면 즉시 기본값을 씀
- [입력] 3행의 고정값 4종은 사용자에게 묻지 않고 그대로 적용함

### 3단계 — 경로 치환 및 작업용 복사본 생성

- `{출력 루트}`는 1단계에서 받은 설계서 Base 디렉토리로 치환함. 그 디렉토리에 이미
  `_shared/프로젝트정보.md`가 있으면 그 `V-12` 값과 이 값이 같은지 확인하고, 다르면
  어느 값을 쓸지 AskUserQuestion으로 확인받음(값을 지어내지 않음)
- `{출력 루트}/_shared/프로젝트정보.md`가 없으면 `[확인필요: 선행 미생성]`으로
  두고 진행함(멈추지 않음)
- 4단계의 모든 위임은 이 작업용 복사본의 절대경로를 가리킴

### 4단계 — 실행 순서대로 위임

0단계 표의 순서ㆍ담당ㆍ병렬 규칙을 지킴. 앞 순서가 "코드를 만들지 않고 멈춤"으로 보고하면 뒤 순서로
넘어가지 않고 그 보고를 그대로 사용자에게 전달함

- Agent 호출 구성: `subagent_type`은 0단계 표의 값을 그대로 지정함. `description`은
  "{프롬프트 파일명} 실행"(예: "01-runtime.md 실행") 형식으로 적음. `prompt`에는 3단계 작업용
  복사본의 **절대경로**를 지정하고 "이 파일을 Read로 전체를 읽고 그 내용을 그대로(요약ㆍ축약 없이)
  따라 수행하라"고 지시함(파일 전문을 Agent 호출 인자 안에 다시 옮겨 적지 않음 — [맥락]의 비용
  특성 참조)
- 순서1ㆍ5ㆍ6ㆍ7(단독 실행)은 `run_in_background=false`로 호출해 결과를 기다린 뒤 다음 순서로
  넘어감. 순서2ㆍ3ㆍ4의 3건과 순서8ㆍ9의 2건은 **하나의 메시지 안에서 여러 Agent 호출을 동시에**
  보냄(순차 호출 금지). 그 구간에 속한 모든 건의 완료 알림을 받을 때까지 다음 순서로 넘어가지
  않음(결과를 추측해 채우지 않음)
- Agent 호출이 오류ㆍ타임아웃으로 끝나면 같은 위임을 최대 1회만 재시도함. 재시도도 실패하면 다음
  순서로 넘어가지 않고 실패 내용(어떤 위임이, 왜 실패했는지)을 사용자에게 보고함
- 병렬 구간(순서2ㆍ3ㆍ4, 순서8ㆍ9)에서 일부만 자가 점검 미통과로 실패하면: 통과한 건은 그대로 두고
  실패한 건만 같은 프롬프트로 재위임함(**재작성 카운터 최대 2회**). 2회 후에도 미통과가 남으면 그
  구간 전체를 멈추고 통과ㆍ미통과 목록을 사용자에게 보고한 뒤 다음 순서로 넘어가지 않음. 구간에
  속한 건이 전부 통과해야 다음 순서로 넘어감
- 순서7(`07-api-ui.md`)은 클로니가 Agent를 부르지 않고 본인이 프롬프트를 직접 수행함
- 위임받은 팀원들의 산출물 사이에 인터페이스 불일치가 발견되면(예: 플로니의 `06-workflow.md`
  상태ㆍ노드 계약과 커넥니의 `04-connector.md`/`05-guardrail.md` 도구 스키마 불일치) 클로니가 최종
  조정함(`AGENTS.md` 팀원 위임 규칙). 조정 없이 뒤 순서로 넘어가지 않음

### 5단계 — 결과 취합ㆍ보고

  그 순서로 되돌려 재작업을 지시함(**재작성 카운터 최대 2회**, 4단계와 동일 카운터). 2회 후에도
  미통과가 남으면 진행을 멈추고 미통과 항목ㆍ시도 내역을 사용자에게 보고함
- 4단계에서 인터페이스 조정이 있었다면 조정 전/후 값과 조정 이유를 보고에 포함함

- 전 순서 완료 후 만든 파일 목록ㆍ시험 결과ㆍ`[확인필요]` 목록ㆍ되묻기로 정한 값 목록ㆍ인터페이스
  조정 이력ㆍ산출물별 실제 담당자와 호출 방식(클로니 직접 / `Agent(subagent_type=...)`)을 표로
